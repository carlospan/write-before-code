# reference/modules · 模块开发文档

> **定位**：绿场 **02** 产出的**可编码模块规格**（信息导向）。编码与验收时以此为真源之一。  
> 上级目录说明见 [../README.md](../README.md)。

---

## 文件从哪来

| 阶段 | 谁写 | 做什么 |
|------|------|--------|
| 02 | 架构师 / IDE Agent | 按 `progress.md` 顺序**生成正文** |
| 03 | 工程师 / IDE Agent | 按本文档编码；可按层级 1 **回写**接口 / 模型等（须注释）；回写契约；progress → 🔍 |
| 04 / 维护者 | 验收 | 独立过一遍；**不改规格正文**；通过后 progress → ✅ |

**不预建空壳**：本目录初始为空；有模块文件再挂链。前置模块须为 ✅ 后，才可为下一模块生成文档并编码。

---

## 命名约定

```text
F{两位编号}-{模块英文名}.md
```

示例：`F01-auth.md`、`F03-orders.md`。编号与 `reference/progress.md` 中的模块行一致。

## 棕地怎么走

模块已 ✅ 之后的行为修补、小演进，走 [`../../specs/`](../../specs/) 任务包，**不必**再开一个新的 `Fxx`（除非整体设计拆出了新模块）。  
若修补改动了跨模块约定，回写 `../global-contract.md`（版本递增）。
