# CI 探针规格（防 drift · 机检）

> **定位**：把总纲「先机检后人判」落成**可自动化检查项**。本文件是规格，不是某语言的完整实现；工程仓应提供 `tools/verify_docs_workflow.*`（或等价）并在 CI 调用。  
> **权威**：检查失败 = 合并阻断（或标红由维护者豁免并留痕）。

---

## 一、探针清单

| ID | 名称 | 输入 | 失败条件 | 严重度 |
|----|------|------|----------|--------|
| P1 | 契约版本单调 | `reference/global-contract.md` 变更日志表 | 版本未按规则递增（兼容追加 +0.1 / 破坏性 +1.0）；或头部「契约版本」与日志最新行不一致；或日志缺日期/摘要/变更性质；或破坏性变更（+1.0）同 PR 无 HITL 批点标记 | 阻断 |
| P2 | progress 状态合法 | `reference/progress.md` | 出现非法流转痕迹：同一 diff 中由非 04/维护者路径将模块标 ✅；或状态值不在 {⬜,📝,🔍,✅,⏸️}；或 ✅ 行无完成时间 | 阻断 |
| P3 | 03 禁止自标 ✅ | 本次 PR diff + progress | diff 显示 progress 某行 `→ ✅`，且同 PR **无** 04 验收结论文件/无维护者签字注释 | 阻断 |
| P4 | 棕地回执含完工段（若有回执） | `specs/tasks/*-回执.md` 与 `specs/archive/**/*-回执.md` | 文件存在但无「完工」段（或等价标题） | 阻断 |
| P5 | 验收记录含机检证据（若有记录） | `specs/tasks/*-验收记录.md` 与 `specs/archive/**/*-验收记录.md` | 结论为通过，但无可识别的测试/CI/命令输出摘要（如 passed/failed、exit code） | 阻断 |
| P6 | 绿场 04 结论可溯源 | 模块标 ✅ 时 | `progress` 备注或旁路文件未指向验收结论（允许维护者签字句：`维护者验收 YYYY-MM-DD`） | 警告→建议阻断 |
| P7 | 死链 | `docs/**/*.md` 相对链接 | 链到不存在的路径 | 阻断 |
| P8 | 任务包契约段（若动契约） | 任务包 `.md` + contract diff | PR 改了 `global-contract.md`，但对应任务包无「契约变更」节或未列段落 | 阻断 |
| P9 | 归档桶必有 INDEX | `specs/archive/*/` 子目录 | 存在归档子桶（内有文件）但缺 `INDEX.md` | 阻断 |

> **文件尚不存在**：P1 / P2 在 `global-contract.md` / `progress.md` 尚未由 01 创建时 **跳过，不算失败**（空模板自检应通过）。P3 无 progress 时同样跳过。  
> 小项目可将 P6 降为警告；P1–P3、P7–P9 建议始终阻断（适用时）。P4/P5 仅在对应文件存在时生效（单线流程下回执/验收记录为可选）。归档后回执仍须能被扫到，故 P4/P5 同时看 `tasks/` 与 `archive/`。

## 二、实现约定（给工程仓）

1. **纯标准库优先**（如 Python），零强制第三方依赖。  
2. **工作区基准**：支持「文档根 = 仓库/`docs`」与「工作区即 docs」两种；用环境变量 `DOCS_ROOT` 或自动探测。  
3. **退出码**：任一阻断项失败 → exit 1；仅警告 → exit 0 并打印 WARN。  
4. **输出**：人类可读摘要 + 可选 JSON（`probe_id`, `ok`, `detail`）。  
5. **CI**：`pull_request` / `push` 必跑；本地 pre-commit 可选。  
6. **参考实现**：同目录 [`ci-probes-reference.py`](./ci-probes-reference.py) 覆盖 P1/P2/P3/P4/P5/P7/P9；工程仓可在此基础上扩展 P6/P8。  

示例调用（工程仓自行落地脚本名）：

```bash
python tools/verify_docs_workflow.py --docs-root docs
# 或工作区即 docs 时：
python specs/ci-probes-reference.py --docs-root .
```

## 三、与人工验收的分工

| 机检（本探针） | 人 / 04 / HITL |
|----------------|----------------|
| 版本号、状态机、文件齐套、有无证据字段 | 业务规则是否真体现、设计意图、PRD 溯源 |
| 有没有跑测试的**痕迹** | 测试断言是否非空壳、是否验对行为 |

探针通过 ≠ 业务验收通过。

---

## 四、豁免

维护者可在 PR 描述写 `docs-probe-skip: P3 原因…`（须列 ID + 原因）。CI 识别后对该 ID 降级为警告；滥用视为流程事故。

hotfix 任务包（标题含 `HOTFIX-` 前缀）自动对 P5 降级为警告；其余探针不变。
