Tutorials are **guided practice**: each step has an expected result, and deliberate simplification is fine. After finishing, the reader should be able to repeat similar work on their own.  
The template itself does not ship a product-specific onboarding lesson; hang the first real tutorial on this page and the root README once it exists.

## Notes when writing tutorials

- One goal per step; say “what you should see when you get here.”  
- Do not paste a full production how-to sequence as-is.  
- Division of labor with [how-to/](../how-to/): learn by walking through → tutorials; look up steps later → how-to.  
- Do not bind to business details of a real customer project.
