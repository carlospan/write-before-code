## Where files come from

| Stage | Who writes | What they do |
|-------|------------|--------------|
| 02 | Architect / IDE Agent | **Generate the body** in `progress.md` order |
| 03 | Engineer / IDE Agent | Code from this doc; may **write back** APIs / models etc. at level 1 (must comment); write back the contract; progress → 🔍 |
| 04 / maintainer | Acceptance | Independent pass; **do not edit the spec body**; on pass, progress → ✅ |

**Do not pre-create empty shells**: this directory starts empty; link files only after they exist. A prerequisite module must be ✅ before the next module’s doc may be generated and coded.

---

## Naming convention

```text
F{two-digit-id}-{ModuleEnglishName}.md
```

Examples: `F01-auth.md`, `F03-orders.md`. IDs must match the module rows in `reference/progress.md`.

## Brownfield path

After a module is ✅, behavior patches and small evolutions go through [`../../specs/`](../../specs/) task packs—**do not** open a new `Fxx` (unless overall design splits out a new module).  
If a patch changes cross-module conventions, write back `../global-contract.md` (bump the version).
