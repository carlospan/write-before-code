# 任务包模板

> 复制本文件改名 `YYYY-MM-DD-任务名.md` 使用。  
> **流程**（详见 [`../SDD-GUIDE.md`](../SDD-GUIDE.md) §2）：**IDE 单线**——同一会话起草任务包、落地编码、工程自验、回写文档。维护者只做 HITL。过程附件按需增减，不必凑齐全套。  
> **人机协作铁律**：产品边界未清时，用 **§2.5 渐进对齐（一块一拍）** 填 HITL——谈定立刻写进本包，再编码放行。见 [hitl-alignment.md](../../how-to/hitl-alignment.md) · 根 README 开篇 ★。  
> **覆盖**（溯源，必填一行）：本包对应 PRD / 模块 / 契约哪一条？例：`F03-orders` 支付回调；或 `global-contract` 错误码段。

---

## Spec（外部行为）

只写可观测结果，不写实现细节。**用增量**，不要重写整份模块规格。

### 当前行为

代码 + 测试里现在是什么样。新能力则写「无」。

### 目标行为（增量）

- **ADDED**：…  
- **MODIFIED**：从「…」改为「…」  
- **REMOVED**：…（须写原因；破坏性变更必须进 HITL）  

无则删掉对应行，不要留空套话。

## 实现（步骤）

1. …  
2. …  
> 可勾选；改动面大时可另附 `-方案.md`。编码与本文同一会话完成。

## 验收（判据）

每条必须可外部判定。默认句式：**WHEN** &lt;条件&gt; **THEN** &lt;可观测结果&gt;。禁止「功能正常」「体验良好」。

- [ ] WHEN … THEN …  
- [ ] WHEN … THEN …  

> IDE 工程自验（须含机检）；产品 / 感受项留给维护者（可另写「仅人判：…」并说明为何不能机检）。需要时落 `-验收记录.md`。

## 契约变更（若有）

- [ ] 无  
- 若有：改了 `global-contract.md` 哪一段；版本须 +0.1；变更日志已写  

## HITL 批点

- 哪些节点须维护者拍板（**一块一拍对齐后写入这里**，勿只留在聊天里）  
- 编码放行单独一条；未放行不大改码  
- 无则写「无」  
> 可标注倾向供参考；**不**代替维护者拍板。
