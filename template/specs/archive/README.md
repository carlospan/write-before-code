# specs/archive · 已闭环任务归档

> **定位**：棕地任务闭环后的**长期过程资产**。从 [`../tasks/`](../tasks/) **迁入**本目录，**不要删除**历史。  
> 过程稿保留「当时 Spec / 决策 / 验收口径」，便于回溯与审计。

---

## 何时迁入

任务包在 `tasks/` 中**同时**满足：

1. Spec 已落地（含当前行为 + 增量）  
2. 编码与工程自验完成  
3. 维护者 HITL（或书面验收）通过  
4. 本桶已从 [`_index-template.md`](./_index-template.md) 复制并改名为 `INDEX.md`（结论 + 契约是否回写 + 本桶文件清单）

然后将该任务**全部相关文件**与 `INDEX.md` 一并迁入对应子桶。  
**没有 INDEX 不得迁出 `tasks/`**——缺结论页等于没闭环。

---

## 桶命名

```text
YYYY-MM-DD-主题/
├── INDEX.md                 ← 必有：结论 + 回写勾选 + 本桶文件清单
├── YYYY-MM-DD-短名.md       ← 原任务包
└── （可选）-方案 / -回执 / -验收记录
```

- 日期取任务**闭环日**（或主任务包上的立项日，团队内统一即可）。  
- `主题` 用短横线连接的简短英文或拼音短语，便于检索。  
- `INDEX.md` 必须写清：一句话结论、ADDED / MODIFIED / REMOVED 摘要、契约是否回写、HITL 日期。模板：[`_index-template.md`](./_index-template.md)。
